# WEISS 第二版图例的 C 实现

本目录为压缩包中的 171 个 `fig*` 文件各提供一个同名 `.c` 入口。`fig1.*` 与 `fig2.*` 是可直接编译的命令行程序；其余图例的入口在对应的 `ch3.c`、`ch4.c`、……、`ch12_*.c`、`chpg.c` 中调用该图例的操作和演示。相邻图例共用类型、节点和辅助函数，以避免在每个文件中重复定义。

在本目录运行 `make check`，可用 `clang -std=c11 -Wall -Wextra -Werror -pedantic` 构建全部程序，并检查 171 个源文件与可执行文件一一对应、每个演示正常退出。测试程序还会检查命令行边界条件，并用独立的穷举求和结果验证 `fig2.5` 至 `fig2.8`。可执行文件保存在 `bin/`。例如：

```sh
cd books/weiss/c
make check
./bin/fig2.8 4 -3 5 -2
./bin/fig9.32
./bin/fig12.24
```

`testkit/` 是从 `os2025/testkit` 的宏注册和进程隔离思路移植的本机测试框架。测试写在 `tests/test_figures.c` 中，`UnitTest` 用于跨多次运行的性质检查，`SystemTest` 直接执行指定的图例程序并检查预期退出码。每个测试独立运行，命令执行限制为 5 秒，单个测试限制为 30 秒；失败会打印退出状态与捕获的输出，并使 `make check` 返回非零。需要查看成功测试的输出时，可运行 `TK_VERBOSE=1 ./bin/test_figures`。框架使用 POSIX `fork`、`execv`、`pipe`，在 macOS 上直接编译运行；它不依赖 `os2025` 目录。

在 VS Code 中打开 Reading Notes 主仓库根目录，并使用 CodeLLDB 扩展。调试算法时，可直接在 `ch*.c` 或 `fig*.c` 中设断点，选择“调试指定图例”并按 F5，然后输入实际要运行的图例编号，例如 `fig3.10`；调试脚本会以 `-O0 -g` 构建该入口。命令行参数可在主仓库根目录 `.vscode/launch.json` 的这一配置中修改 `args` 数组，例如 `fig2.8` 使用 `["4", "-3", "5", "-2"]`。调试测试断言时，选择“调试 TestKit 指定用例”，输入 `tests/test_figures.c` 中的用例名，例如 `binary_search_found`；此模式让测试正文在调试器进程中运行，便于命中断点。被测试的 `fig*` 程序仍通过子进程执行，因此其算法断点应使用“调试指定图例”。普通的单项隔离测试可运行 `./bin/test_figures --case binary_search_found`，修改完成后运行 `make check`，需要从头验证全部构建时运行 `make -B check`。

`fig2.5` 至 `fig2.8` 的数组元素取值限制为 ±10⁹，分别限制最多 200、10000、100000、100000 个元素，以避免求和溢出并控制三重循环的运行量。二分查找 `fig2.9` 要求输入数组非降序，位置从 1 开始；找不到时返回 0。

教材代码包含刻意展示的问题和留白，C 版做了可运行的补全：`fig1.3` 对正整数不终止，因此在入口给出说明；`fig3.16` 先保存后继再释放节点；`fig4.17` 通过指针参数清空树；`fig4.39` 补上对称的右子树情况；`fig7.10` 给 `NumElements` 赋值；`fig9.65` 修正未赋值的顶点；`fig9.66`、`fig9.67` 处理 DFS 根的割点特例；`fig10.54` 使用 64 位乘法并修正赋值；`fig12.38` 修正原条件中的笔误。只有类型声明的图例配有实际使用该类型的演示。

个别图例需要明确实现选择：`fig10.62` 是使用固定底数 2 的 64 位单轮素性测试演示，不能当作任意精度或确定性素性判定；`fig12.16` 用左倾红黑树表达旋转和颜色翻转；`fig12.47`、`fig12.49` 用定长二维堆，删除时扫描指定坐标并重建堆。目录、图和棋盘类伪代码使用代码中的固定样例数据。`make check` 验证这些样例的构建和运行，以及上述命令行和最大子序列和测试，未验证所有可能输入下的算法性质。
