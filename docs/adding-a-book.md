# 接入一个新的笔记子项目

每本书放在 `books/<id>/`，使用稳定的小写 ID。一个子项目保存一个全书总览和按章划分的独立笔记文件，来源、辅助资源、程序、维护规范与检查工具都在自己的目录内。正式内容仅保留一份，公共发布层按需增加阅读导航与资料页。

建议新项目采用 `notes/`、`code/`、`assets/`、`tools/` 和 `README.md`；已有项目允许保留必要的内部路径，在 `books/catalog.json` 中登记实际目录。迁入 Weiss 的 `c/` 与 `notes/tools/` 即采用这一方式。先检查文件和链接，不批量改章节版式或重排题号。

接入顺序：

1. 建立问题单，明确教材版次、来源、范围、既有文件与恢复点；新增子项目只复制授权资料，不导入其他仓库、运行产物或凭据。
2. 创建目录及全书入口，写清内容规范、程序维护源、相对资源关系和具体检查命令。
3. 在 `books/catalog.json` 登记 ID、目录、入口、发布前缀、校验器、预期页数和题数。核对 ID 和发布前缀唯一。
4. 扩展 `tools/project.py` 的按书验证分派，接入有意义的内容/程序检查；维护 `deploy/build_portal.py` 的源文件清单、`deploy/reader_views.py` 的书籍名与资料转换，以及 Nginx 的入口规则和 `deploy/verify_portal.py` 的检查。注册表负责目录事实，新增书籍的专用程序检查和出版转换仍需明确接入代码。
5. 给 `portal/index.html` 增加书架入口，同步根 README 与文档索引。新增源码边界或工具链时修改 `.project-governance.json`，再使用治理技能预览、应用并校验，不手改受管区块。
6. 运行结构、完整程序、归档和本地 HTTPS 检查；在宽屏与手机宽度检查全书地图、章间导航、目录、习题深链接和下载入口。

发布 URL 以 `<publish_prefix>/` 为边界，不将源仓库的 `books/` 路径暴露为阅读地址。共享构建应能在独立克隆中完成；避免引用其他本机工作目录。原书资料只有在明确列入构建清单且可发布时才进入站点包。

书籍内容与计算规则分别遵循自己的权威规范，见 [规则职责索引](rules/README.md)；发布、恢复和证据标准遵循 [统一部署说明](../deploy/README.md)与 [测试设计](../test/T001-project-merge.md)。
