# 开发与变更工作流

<!-- project-governance:managed:start -->
治理级别：`controlled`。

重要变更必须使用问题单、计划、测试设计和里程碑记录。核心技术栈、业务规则、架构、API、Schema、安全和部署变更还必须经过变更控制；难以回退的决策必须建立 ADR。

## 变更闭环

1. 阅读适用的权威文档并检查当前状态。
2. 在问题单或计划中明确范围、风险、验收标准，以及代码、测试、文档和数据的影响面。
3. 行为变更必须先设计测试，并确认测试能因目标行为尚未实现而失败。
4. 实施最小且完整的变更，不得修改无关内容。
5. 运行已登记检查，调查失败原因，不得隐藏、删除或弱化失败测试。
6. 在同一 PR 或交付批次中同步所有受影响的权威文档与变更记录。
7. 如实报告变更、验证证据、文档同步情况和仍存不确定性。

## 变更影响矩阵

| 变更类型 | 同一变更中必须同步 | 最低验证 |
|---|---|---|
| 核心技术栈或兼容基线 | `.project-governance.json`、`TECH.md` 当前基线与变更索引、锁文件/迁移说明；难以回退时增加 ADR | 构建、测试、兼容性与回滚验证 |
| 公式、统计口径、舍入、精度、单位、币种、时间边界等业务/计算规则 | `docs/rules/` 权威规则、受影响 API/报表/用户说明、测试设计、可执行回归测试 | 新旧示例、边界、异常和回归验证 |
| API、数据结构或数据库 Schema | API/Schema 契约、兼容与迁移说明、回滚方案 | 契约测试、迁移与回滚验证 |
| 环境变量、服务、端口或环境差异 | `.project-governance.json`、`docs/environments.md`、`.env.example` 非秘密键名 | 配置加载与环境验证 |
| 用户可见行为 | README、用户文档、API/报表说明 | 用户路径或验收场景 |

## 关闭门禁

- 未完成文档影响评估，不得标记完成。
- 有文档影响但未同步，不得标记完成。
- 判定无需更新文档时，必须在问题单或交付说明中记录判断依据。
- 代码、测试、规则文档出现口径冲突时，以未完成处理，不得选择性宣称某一项正确。

## 工作记录

重要工作必须使用 `issues/`、`plan/`、`milestone/` 和 `test/`；难以回退的选择必须在 `docs/decisions/` 中新增决策记录。

记录应尽量只追加、不删除。不得通过改写历史来掩盖曾经的调查结果或失败。

## 项目专属工作流

普通笔记修订按影响范围运行按书检查并完成桌面/窄屏验收；目录、源码维护源、发布路由和计算规则变化使用问题单及测试设计。重要迁移见 [I001](../../issues/I001-project-merge.md)。生产任务的授权以用户实际指令为准，不以工作记录自我批准。
