# P001 · 子项目迁移实施计划

关联 [I001](../issues/I001-project-merge.md)。目标是在原仓库内完成可恢复的整合，保留当前用户改动和发布地址。

1. 读取两条用户引用聊天、两项目规范、Git 状态和发布实现；逐文件建立来源与 SHA-256 清单，备份当前源文件及未提交改动。
2. 随机过程内容移动到 `books/stochastic/`，Weiss 的正式资料复制到 `books/weiss/`；保留每本内部相对路径和原目录，排除生成二进制及无关工程。
3. 将 `books/catalog.json` 作为目录登记，接入根命令、统一构建和预览；调试入口指向迁入的 C 图例。
4. 采用 `generic + controlled` 配置，通过指定治理技能完整预览、应用、校验。README 与忽略规则作为项目自主管理文件审阅。
5. 写清维护、部署、证书、版本原子切换、回滚、文档职责和新增书籍流程。更新文档变化造成的当前哈希绑定，保留历史值。
6. 运行两书完整检查、统一打包、重复构建、隔离克隆/复制验证、本地 HTTPS、浏览器代表路径和来源字节对比；填写实际结果。

依赖：Python 3.10+、Clang、Make、Poppler/pdftotext、Node.js；本地 HTTPS 验证另需 Nginx/OpenSSL。所有验证输出保存在根 `tmp/` 或忽略的发布目录。

恢复点与停止条件见 [迁移记录](../docs/migration-20261012.md)。发现源文件被其他任务同时改动、资料身份不符、关键检查失效或现有布局被改变时，停止依赖操作，检查差异后恢复到保留的副本；不用重置 Git 来清除用户改动。
